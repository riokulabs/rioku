# Style Guide

Each rule here is enforced by a linter, hook, or CI check. Unenforceable opinions live in
[coding-guidelines](../ai-development/coding-guidelines.md), not here.

---

## Go

**Enforced by:** `gofmt` + `goimports` (pre-commit hook), `golangci-lint` (PR CI), `go vet` (pre-push hook).

- **Stdlib-first.** Reach for the standard library before adding a dependency. Justify every new module in the PR description.
- **No ORM.** All persistence is raw SQL via the per-dialect store packages (`internal/store/sqlite`, `internal/store/postgres`, `internal/store/mysql`). Do not add `gorm`, `ent`, `sqlboiler`, or similar.
- **Race detector mandatory.** Every PR runs `go test -race ./...` (`make test-race`). Tests that only pass without `-race` are broken tests, not broken detectors.
- **Table-driven tests.** Use `t.Run` subtests with a named `tests []struct{...}` slice. No flat sequences of `assert` calls.
- **Explicit error handling.** Every error must be handled. `_ = someErr` is a lint error. Wrap errors with `%w` to preserve the chain; do not log-and-discard.
- **`log/slog` for logging.** Use `slog.Logger` (injected, never global). No `fmt.Printf` or `log.Printf` in production paths.
- **`rerr` for handler errors.** REST handler errors must use the `rerr` pattern (structured HTTP error with code + message). See `internal/gateway/errors.go` for the current implementation; a dedicated `rerr` package is planned (tracked in #264).
- **Import grouping.** Three groups separated by blank lines: (1) stdlib, (2) third-party, (3) internal (`github.com/riokulabs/rioku/...`). `goimports` enforces this on commit.
- **`make build-daemon` not `go build`.** The Makefile injects correct ldflags and outputs to `bin/`. Raw `go build` drops a binary in the working directory.

## TypeScript

**Enforced by:** ESLint + Prettier (pre-commit hook on `packages/web/**`), `tsc --noEmit` (PR CI), Vitest (PR CI).

- **Mantine direct.** Use Mantine components and theme hooks directly in `packages/web/`. There is no custom design-system layer, no token package, and no `packages/ui/`. Do not create one.
- **Orval-generated hooks.** All API calls go through the hooks generated by Orval from OpenAPI. Do not hand-write `fetch`/`axios` calls for routes already in the spec.
- **TanStack Router + Query.** Routing is TanStack Router; server state is TanStack Query. Do not introduce React Router, SWR, or a second query library.
- **No new state libraries.** Global client state uses React context or Zustand (already present). Do not add Redux, Jotai, Recoil, or similar.
- **Boundaries-enforced imports.** `packages/web/` must not import from `packages/daemon/` or `packages/proto/` directly — only from the generated client in `packages/web/src/api/`.
- **ESLint rules are blocking in CI.** `@typescript-eslint/no-unused-vars` is an error (unused vars prefixed with `_` are allowed). `no-console` is a warning except in test files.
- **Prettier formats on commit.** Do not reformat manually; let the hook run Prettier. If Prettier and your editor disagree, the hook wins.

## Protobuf

**Enforced by:** `buf lint` (pre-commit hook on `packages/proto/**`, PR CI via `make proto-lint`).

- **`rioku.v1` package.** All proto files use `package rioku.v1;` with `option go_package = "github.com/riokulabs/rioku/proto/gen/go/rioku/v1;riokuv1";`. The Go alias is always `riokuv1`.
- **buf lint: STANDARD ruleset.** See `packages/proto/buf.yaml` for the active lint rules and the narrow set of exceptions (`PACKAGE_VERSION_SUFFIX`, `RPC_REQUEST_STANDARD_NAME`, etc.). New files must not add new exceptions without a documented reason.
- **google/api conventions.** HTTP bindings use `google.api.http` annotations. Field names follow `lower_snake_case`. Message names are `PascalCase`. RPC names are `PascalCase` verbs (`ListRoutes`, `CreateTenant`).
- **Regenerate after changes.** Run `make proto` after editing `.proto` files. Never hand-edit generated files under `packages/proto/gen/`.

## Migrations

**Enforced by:** CI store-matrix check (5 required checks: SQLite, Postgres, MySQL/Galera x2, Galera-restart). The matrix job fails if migration version numbers drift across dialects.

- **Three dialect directories.** Every migration lives in all three of `internal/store/sqlite/migrations/`, `internal/store/postgres/migrations/`, and `internal/store/mysql/migrations/`. Version numbers must be identical across dialects.
- **Never edit a landed migration.** Once a migration file is merged to `main`, it is immutable. Corrections go in a new migration.
- **`make test-race` includes store matrix.** Running `make test-race` locally exercises SQLite; CI exercises all three. If a migration passes SQLite but fails Postgres, CI catches it.
- **Describe the migration.** The file name must describe the change (`0012_add_ai_provider_index.sql`), not just increment a number.

## Commits

**Enforced by:** `cliff.toml` (changelog generation fails on non-conforming types), Conventional Commits check in PR CI.

- **Format:** `<type>(<optional scope>): <short summary>`. Summary is imperative, lowercase, no trailing period. Max 72 characters for the header.
- **Allowed types:** `feat`, `fix`, `chore`, `docs`, `test`, `refactor`, `ci`, `style`.
- **No AI references.** Do not include AI tool names, model names, or `Co-Authored-By:` lines for AI tools in commit messages. This is a hard project rule documented in the repository root `CLAUDE.md`.
- **Squash merge.** PRs are squash-merged. The squash commit message is the PR title. Write PR titles in Conventional Commits format.
- **Signed commits required.** All commits must be signed (SSH key or GPG). Configure signing once with `git config --global commit.gpgsign true` or equivalent.
